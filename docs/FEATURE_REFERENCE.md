# FEATURE REFERENCE

差別化の主張のひとつに「**安定性と機動性は Sable 相当**」があります。
そのためには Sable がどんな機能を持っているかを把握し、kaleido.chat で何を実装するかを決める必要があります。

この文書は**機能の棚卸しと仕分け**のためのものです。

---

## ⚠️ ライセンス上の重要な注意

| | |
|---|---|
| [Sable](https://github.com/SableClient/Sable) | AGPL-3.0-only（[Cinny](https://github.com/cinnyapp/cinny) のフォーク） |
| kaleido.chat | **MIT** |

**AGPL-3.0 のコードを MIT のプロジェクトへコピーすることはできません。**

したがって:

- ✅ **参照してよいもの** — どんな機能があるか、という事実
- ✅ **参照してよいもの** — 公開されている技術構成（何のライブラリを使っているか）
- ❌ **してはいけないこと** — ソースコードのコピー、部分的な流用、翻案

実装はすべて独自に行います。**「Sable を見ながら書く」のではなく「Sable にある機能を、自分で設計して書く」**という関係です。

## Sable の技術構成（事実として記録）

kaleido.chat とは別物ですが、比較対象として記録しておきます。

| 項目 | Sable |
|---|---|
| 言語 | TypeScript |
| UI | React + folds |
| スタイル | vanilla-extract |
| 状態管理 | jotai |
| ルーティング | react-router-dom |
| Matrix SDK | matrix-js-sdk |
| 暗号化 | `@matrix-org/matrix-sdk-crypto-wasm`（matrix-rust-sdk の crypto crate） |
| ビルド | Vite |
| 国際化 | i18next |
| デスクトップ | Tauri 2 |
| テスト | Vitest + Playwright |

**注目点**：Sable も暗号化には matrix-rust-sdk を使っています。「暗号化を Rust に任せる」という判断は Matrix エコシステムで共通しています。

**日本語化について**：Sable は UI 文字列がコンポーネントへ直接ハードコードされており、i18n の配線はあるものの実際のロケールはほぼ空です。**「日本語対応」が kaleido.chat の差別化として成立するのはこのためです。**

### 実装しない（現時点の判断）

| 機能 | 理由 |
|---|---|
| 複数アカウント切替 | 移行組の主要な要求ではない。複雑さに見合わない |
| カスタムテーマ・テーマカタログ | ダークオンリー方針（[DESIGN_LANGUAGE](DESIGN_LANGUAGE.md)） |
| ライトモード | 同上 |
| GIF ピッカー | 外部APIキーへの依存が発生する |
| ステッカー | 同上 |
| 開発者向けツール | 一般利用者向けのため |
| Bot 管理・プラグイン | スコープ外 |
| 任意ホームサーバーの指定 | matrix.org 固定（[DESIGN](DESIGN.md) §4） |

**この仕分けは変更可能です。** 実装しないと決めたものも、要求が出れば再検討します。

## 機能を足すときのルール

差別化の主張「**バグが無い**」は、機能を足すたびに弱くなります。

機能を追加する前に確認します。

1. Discord からの移行組が、それが無いと**移行できない**か？
2. 既存の機能を壊さずに足せるか？
3. [PERFORMANCE_BUDGET](PERFORMANCE_BUDGET.md) を割らないか？

「あると便利」だけでは足しません。
