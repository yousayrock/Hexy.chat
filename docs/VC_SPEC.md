# VC SPEC — ボイスチャット

## 方針

Hexy.chat のターゲットは Discord からの移行組であり、**ボイスチャットは最終的に必須**です。
しかし v0.1 では実装しません。差別化として掲げた「バグが無い」を守るためです。

WebRTC と SFU の接続まわりは、Matrix クライアント実装のなかで最もバグが出やすい領域です。
テキスト基盤が安定する前にここへ手を出すと、アプリ全体の信頼性が落ちます。

| バージョン | 対応 |
|---|---|
| **v0.1** | 実装しない。UIには出す。通話は公式 Element Call へ外部リンクで逃がす |
| **v0.2** | MatrixRTC + Element Call Embedded + LiveKit で内蔵する |

---

## v0.1 の挙動

### ボイスチャンネルは表示する

チャンネル一覧に `🔊` 付きのボイスチャンネルを**表示します**。Discord から来た人にとって、ボイスチャンネルが見えないことは「機能が無い」ではなく「壊れている」と受け取られるためです。

### 選択したときの画面

中央ペインにプレースホルダーを表示します。

```text
🔊  <チャンネル名>

いまは、高速で安定したテキストチャット基盤の開発を優先しています。
ボイス機能は今後のアップデートでお届けします。

[ ブラウザで通話を開く ]
```

隠さず、開発中であることを正直に書きます。

### 「ブラウザで通話を開く」

公式の Element Call へ、ルームID付きで**外部リンク**します。

```text
https://call.element.io/room/#/<room_id>
```

> **注意**：遷移先は `element.io`（マーケティングサイト）ではなく **`call.element.io`** です。
> 正確なURL形式は実装時に Element Call の仕様を確認してください。

`target="_blank"` かつ `rel="noopener noreferrer"` で開きます。

**この設計の意図**：WebRTC / SFU の接続バグをすべて公式側に背負わせ、Hexy.chat 自身の「バグが無い」という信頼性を守ります。

### UIに出すもの・出さないもの

| | v0.1 |
|---|---|
| ボイスチャンネルの一覧表示 | ✅ 出す |
| 参加中メンバーの表示 | ❌ 出さない |
| マイク・スピーカーのミュートボタン | ❌ 出さない（機能がないため飾りを置かない） |
| 通話開始ボタン | ⚠️ 「ブラウザで通話を開く」外部リンクのみ |

## v0.2 の設計

### 採用する仕様

| 層 | 採用するもの |
|---|---|
| 通話状態の標準 | **MatrixRTC**（MSC4143）。誰が通話に参加しているかを Matrix の状態イベントで表す |
| 通話クライアント | **Element Call Embedded**（widget として埋め込む） |
| 音声・映像の中継 | **LiveKit**（SFU）。MSC4195 が Matrix と LiveKit の橋渡しを定める |

### なぜ Element Call を埋め込むのか

自前で WebRTC クライアントを書くと、コーデック・NAT越え・E2EE 鍵配布・複数人の負荷制御をすべて自分で背負うことになります。

Element Call を **iframe の widget として遅延読み込み**すれば、**自分の WASM バンドルサイズは増えません**。通話を開始するまで一切ロードされないためです。これは [PERFORMANCE_BUDGET](PERFORMANCE_BUDGET.md) の目標と両立します。

### 必要になるサーバー構成

自前運用する場合、以下が必要です。

| コンポーネント | 役割 |
|---|---|
| **LiveKit SFU** | 音声・映像の中継。独立したサブドメインに置く必要がある |
| **[lk-jwt-service](https://github.com/element-hq/lk-jwt-service)** | Matrix ユーザーに LiveKit への接続権限（JWT）を発行する認可サービス |

いずれも Docker での運用が前提で、ドメインと TLS 証明書が必要です。

### v0.2 で解く必要がある課題

1. **Leptos から widget API を橋渡しする** — Element Call は `postMessage` ベースの widget API で通信します。Leptos（Rust/WASM）から JS interop でこれを扱う必要があります
2. **MatrixRTC の状態イベントを読む** — 誰が通話中かをチャンネル一覧やメンバー一覧へ反映する
3. **LiveKit を自前運用するか、公開インスタンスに乗るか** を決める
4. **回線の到達性検証** — IPv6 オンリー環境での LiveKit 接続は事前検証が必要

### 段階案

v0.2 をさらに分けることを検討します。

- **v0.2a**：Element Call を widget として埋め込む。LiveKit は公開インスタンスを使う
- **v0.2b**：LiveKit + lk-jwt-service を自前運用へ切り替える
